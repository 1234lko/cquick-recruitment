## 任务 1：命令行体验发布/订阅
<说明：谁在发布、谁在订阅，消息怎么流动的>
 talker.py 是发布方，持续向外发小球位置消息； listener.py 是订阅方，监听同一个话题。
消息流向：talker不断把小球坐标发到话题上，ROS中间件负责转发，只要节点订阅了这个话题，就能收到数据。发布者不用管有多少个订阅节点在接收消息。

## 任务 2：发布者 + 订阅者节点
<说明：跑通了什么，改了什么参数、观察到什么变化>
跑通了  talker.py  和  turtle_chase.py 。
talker持续发布小球位置话题  /ball_pos ；turtle_chase这个节点，一边订阅小球位置，一边读取乌龟自身的位置，算出误差之后，发布速度指令，控制小乌龟追小球。
我修改的参数是talker的消息发布频率。频率调高，小球位置更新更快，乌龟追踪反应更灵敏；频率调低，乌龟动作就会滞后，跟不上小球。
## 任务 3：自定义消息 + 三种通信方式
<说明：自定义消息怎么定义的；用你自己的话讲清话题/服务/动作的区别和场景>
在包里面的msg文件夹新建.msg文件，定义好消息里面的字段，像小球的x坐标、y坐标、编号。写完之后修改CMakeLists.txt和package.xml，编译成功，代码里面就可以导入使用这个自定义消息类型。
 话题：持续不断地单向发数据流，适合一直更新的数据，比如传感器读数、乌龟实时位置，乌龟追逐实验用的就是话题。
 服务：发一次请求，收到一次回复，事情处理完通信就结束，适合一次性的简短操作。
 动作：用来处理耗时比较久的任务，运行的时候可以不断反馈进度，还能随时取消任务，适合机器人自主点位导航这种场景。
